LanceDB gives you two ways to work with multimodal data, both built on the open
[Lance](/enterprise/v8-2-0-test/basics/lance) format.

**LanceDB OSS** is an embedded library. Run it inside your application
with tables on local disk or in object storage. You control the application,
its resources, and table maintenance, without a separate database service.
[Try the quickstart](/enterprise/v8-2-0-test/quickstart) to create a table and run your first search.

**LanceDB Enterprise** is a multimodal lakehouse for data curation, feature
engineering, search, and training data access. It adds query-serving capacity,
data caching, and background operations for teams working with shared
multimodal datasets.
[Connect to Enterprise](/enterprise/v8-2-0-test/basics/connect#enterprise) when your cluster is ready.

## Why choose Enterprise? {#why-enterprise}

### Serve growing workloads {#serving}

Add query-serving capacity as more applications and users depend on your data.
Enterprise spreads query traffic across a fleet and caches frequently read
table data near compute, reducing repeated reads from object storage. Query
serving and background work use separate resources, so you can size each for
your workload. See [Enterprise architecture](/enterprise/v8-2-0-test/enterprise/architecture).

### Reduce operational work {#operations}

Let the service handle routine table maintenance instead of scheduling it in
application code. Enterprise handles background [compaction](/enterprise/v8-2-0-test/maintenance/compaction) and can
[clean up old table versions](/enterprise/v8-2-0-test/maintenance/cleanup) according to your retention
policy. Configure these maintenance tasks for your Enterprise cluster so each
application does not have to schedule them.

### Fit your deployment requirements {#deployment}

Choose a managed deployment or bring LanceDB into your own cloud account.
Enterprise integrates with OpenTelemetry for metrics and traces, helping your
team monitor the service alongside your applications. Talk to us about your
cloud, networking, and operational requirements to plan the right deployment.
The [Enterprise overview](/enterprise/v8-2-0-test/enterprise) explains the available options.

### Connect your data workflows {#workflows}

Use the same tables for retrieval, dataset preparation, and training data access.
With its [SQL endpoint](/enterprise/v8-2-0-test/basics/sql) enabled, Enterprise supports analytical
[curation](/enterprise/v8-2-0-test/curation), including joins, grouping, and sampling.
[Feature engineering](/enterprise/v8-2-0-test/feature-engineering) adds derived columns and tables;
computed columns and materialized views require the corresponding features to
be enabled for your Enterprise cluster.
[Geneva](/enterprise/v8-2-0-test/geneva) runs Python feature backfills as distributed jobs.
[Training data loaders](/enterprise/v8-2-0-test/training/data-loading), available in both offerings,
read the resulting datasets for model training.
