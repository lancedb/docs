When working with multimodal data at scale, [LanceDB Enterprise](/enterprise/v1-10-0/enterprise) makes it easy
to define, extract, and transform raw data into useful information and features for your
AI applications. LanceDB Enterprise's _Multimodal Feature Engineering_ package is designed to improve
the productivity of AI engineers operating at immense scale.

With an API designed to leverage LanceDB's optimized data storage and retrieval, it
streamlines prototyping extraction and transformation tasks, performing experiments, exploring your
data, scaling up execution, and moving to production.

LanceDB Multimodal Feature Engineering enables researchers to seamlessly transition from
experiments in local notebooks to fully-managed distributed job execution on datasets with
billions of rows.

<Card>
The `geneva` Python package is currently only available as part of
[LanceDB Enterprise](/enterprise/v1-10-0/enterprise). Please [contact us](https://www.lancedb.com/contact) if you're interested
in scaling up your feature engineering workloads for your AI and multimodal use cases.
</Card>

Feature engineering itself is not Enterprise-only: LanceDB OSS has
[computed columns](/enterprise/v1-10-0/feature-engineering/add-computed-column) and
[materialized views](/enterprise/v1-10-0/feature-engineering/materialized-views), which need no
extra package. See [Feature engineering](/enterprise/v1-10-0/feature-engineering) to choose between
them and Geneva.

The `geneva` package uses Python [User Defined Functions (UDFs)](/enterprise/v1-10-0/geneva/udfs/udfs) to define features
as columns in a Lance dataset. Adding a feature is straightforward:

<Steps>
  <Step>
  Prototype your Python function in your favorite environment.
  </Step>
  <Step>
  Wrap the function with a small UDF decorator (see [UDFs](/enterprise/v1-10-0/geneva/udfs/udfs)).
  </Step>
  <Step>
  Register the UDF as a virtual column using `Table.add_columns()`.
  </Step>
  <Step>
  (Optional, advanced) Override where the job runs — see [Advanced Execution Contexts](/enterprise/v1-10-0/geneva/jobs/contexts). On LanceDB Enterprise, distributed job execution is fully managed, so most users can skip this step.
  </Step>
  <Step>
  Trigger a `backfill` operation (see [Backfilling](/enterprise/v1-10-0/geneva/jobs/backfilling/)).
  </Step>
</Steps>

<Tip>
You can build your Python feature generator function in an IDE or a notebook using your project's Python versions and dependencies. `geneva` will automate much of the dependency and version management needed to move from prototype to scale and production.
</Tip>

Ready to write your first feature? Head to [Getting Started](/enterprise/v1-10-0/geneva/getting-started).

## Geneva and Functions {#functions}

[Functions](/management/function) are the recommended way to fill columns with
Python on a deployment. They are part of the `lancedb` package and run on the
deployment that enables them. Geneva remains available for existing pipelines.
The concepts correspond:

| Geneva | Functions |
| --- | --- |
| `geneva.connect(...)` | `lancedb.connect(...)`, with the same URI, endpoint and key |
| `@geneva.udf(data_type=...)` | `@udf` from `lancedb`, typed by its annotations |
| `tbl.add_columns({"col": udf})` | register with `db.create_function_async(fn)`, then `table.add_columns({"col": version(x=col("x"))})` |
| `tbl.backfill("col")` | `table.refresh_column_async("col")`, a [job](/basics/jobs) |
| a manifest's pip or conda packages | `pip`, `conda` and `env` on `@udf` |

Moving a column means registering its UDF as a Function and declaring the column
